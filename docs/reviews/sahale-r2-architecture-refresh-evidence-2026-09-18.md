## Architecture decisions and reconciliation

The new canonical owner `docs/architecture/context-coordination.md` is warranted
because neither Knowledge Authority nor the lower-level compiler owns semantic
cross-source task planning. It defines the responsibility and boundaries while
referencing the existing authority, AI, operating-model, platform, capability,
and compilation owners. No new foundation, formal schema, runtime, or source
registry is introduced. Source metadata establishes ownership, authority,
sensitivity, freshness, retrieval, permitted cross-domain use, provenance,
bounded projections and defined fallback behavior. Probabilistic category
planning cannot invent these contracts or grant access/action authority.

Platform Architecture owns conversation/workspace/Project/capability distinctions,
optional escalation from conversational use, incubation, simple functional
workspace names, and Sahale/Homelab relationships. It separates Homelab's
workspace, source/engineering-domain and execution roles. Hosting a Sahale
service never transfers capability ownership. Repository Architecture retains
the accepted specialized-repository boundary and separate restricted desired
state, live observation and protected-secret boundaries without further design.

Personal AI no longer mandates a separately named subsystem; useful AI, context,
automation, coordination and interaction responsibilities stay with the existing
foundations. AidenOS no longer mandates a current product or future UI outcome.
A possible Sahale UI remains under Interaction and Experience, deferred until
useful capabilities earn it. Explicit legacy identifiers, opportunity records,
historical roadmap sequence and historical evidence remain intact. The current
strategy explicitly qualifies the dated July hub proposal with the UI deferral.

Owner reports of the Sahale ChatGPT Project, functional workspaces, revised
instructions and bounded `sahale-orientation.md` are supplied interaction/design
evidence. They were not independently inspected or copied wholesale, and no
Project configuration was changed. Canonical durable architecture can inform
future derived orientation without making a Project canonical.

W2 remains the published phase. R2 is selected with the existing schema's
`selected` lifecycle and a pending exact-candidate acceptance decision. Empty
R2 typed evidence-reference arrays are intentional: the schema requires a real
commit containing each linked evidence path. This new record is uncommitted;
Current Mission links it without fabricating an immutable identity. Authority
sentinels and historical publication links remain unchanged.

The public-surface suite's presentation heading and current-state expectations
follow R2. All privacy classifiers, allowlists, hashes, literal counts and
policy behavior remain intact. The one affected line-number disposition moves
with its unchanged existing literal; it grants no new exception.

## Risk, rollback and deferrals

The principal risks are conflating presentation with machine identity, replacing
the deterministic compiler with an AI-selected source model, transferring source
ownership to a Project or host, implying a production runtime, or overstating
acceptance/publication. The patch explicitly distinguishes each boundary.
Rollback would be a bounded restoration of the reviewed documentation,
registration/state/test expectation changes and registered regeneration, under
applicable authority. There is no runtime or data migration to reverse.

Coordination implementation, automatic retrieval/routing, dedicated UI, identity
migration, Homelab extraction/restricted-source creation, School storage changes,
external configuration, publication and deployment remain deliberately deferred.
